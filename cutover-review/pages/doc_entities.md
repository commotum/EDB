# Entities page review

`docs-2/02_core_concepts/04_entities.md` already agrees with NORTHSTAR: six-field examples, one source per transaction, captured point-in-time navigation, and distinct entity values independent of contribution count. Keep the page unchanged. Read the full page, NORTHSTAR, timestamp reference, CUTOVER, and the three supplied design talks.

Observed gap: `Entity::read_direction` obtains forward values from `DatabaseValue::values`, which already removes duplicate source contributions using stored equality, then applies `Vec::dedup` using logical `Value::Eq`. Top-level BigDecimals `1.0` and `1.00` have distinct stored identity but compare logically equal. Entity navigation can therefore lose a value that Pull correctly retains. The existing stored-value regression tests values/Pull/programs, but not Entity.

Bounded objective: retain the same stored values through forward entity navigation, while reverse references and component edges remain independent of source multiplicity. Reusing `DatabaseValue::values` preserves local reasoning: visibility stays in the read engine, value projection stays in values, and Entity only wraps results. A second stored-value projection in Entity would duplicate policy and make changes harder; changing global `Value::Eq` would alter unrelated logical semantics. Selected fix: deduplicate only reverse reference IDs (forward values are already distinct), with focused tests for decimal scales and source/temporal navigation.

Acceptance: eager and speculative-overlay forward Entity collections retain scales 1 and 2; multiple contributors do not multiply references or components; cross-source withdrawals remain absent under source predicates and since/as-of boundaries. Inspect existing Pull, stored-value, database-value identity, and visibility logs rather than rerun all suites. Shared-code ownership requested from root before changes.
