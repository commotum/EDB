# Language support review

The page presents two data frontends to one Rust engine: native types and EDN, with CLI process invocation for other languages. It already requires a request key and one request-level source for durable transactions, including the automatic timestamp. NORTHSTAR's source coordinate does not require changes to the page's query example, crate names, EDN notation, or CLI argument order.

The bounded concern is whether these entry points actually retain native behavior and source identity, and whether the documented Rust examples and EDN value distinctions are executable. Potential causes are stale public exports, separate frontend semantics, premature client-side source resolution, or lossy EDN conversion. An additional SDK/REST/C ABI would create a new boundary without addressing a gap in the documented behavior; a wrapper would duplicate existing mechanisms. The selected approach is to inspect existing public exports, EDN lowering/conversion, CLI IO and source admission, query execution, and transport, then reuse acceptance evidence for unchanged paths. Change implementation only for a concrete uncovered defect.

This keeps representation, execution, and durable transport independent: EDN data compiles to the existing query/preparation machinery; transaction source remains request data and resolves during assessment; other languages compose through ordinary process IO. Preserve local reasoning and ability to change by leaving these established boundaries intact.

Acceptance: both Rust snippets use exported symbols and the same bootstrap query; EDN serializes relation results as a set of vectors; reader/writer preserves native type tags and rejects invalid stored values; CLI reads --file - from stdin and writes EDN on stdout; transactions require structural --source before storage and carry deferred source through receipt-first submission; existing live native/transactor workflow logs and integrated interface/query/Pull tests cover these unchanged behaviors. Record exact findings and any edits below.

## Actual review and results

No assigned documentation or implementation edits were necessary. Public exports in `src/lib.rs` and Cargo's `edb-core` package provide every listed type/module. `DataPattern::new` uses the default database `$`; optional fact source remains a separate datom coordinate. `edn_query` binds data into native `PreparedQuery` and executes the same native engine, without host evaluation. `edn_pull` compiles selector data into native Pull patterns, preserving deferred read identifiers and explicitly registered transforms. `edn_transaction` retains unresolved canonical forms; request-level `EntityRef::from_edn` retains canonical EDN until assessment. Local transport encodes the submission directly; authority checks complete request digest and exact receipts before fresh source resolution/clock selection.

`edn_value` preserves E/A/V/T/S/bool in reports and namespaced native tags. The reader represents keywords, symbols, strings, numeric domains and collection shapes separately. Stored conversion rejects nil, characters, maps, sets and unknown stored tags; general query conversion remains a separate domain. CLI `data.rs` uses these public adapters, reads `--file -` from stdin, and prints EDN plus newline on stdout. Its transact/with argument admission requires structural source before opening storage. Queries execute locally; transact invokes the existing local or TLS transaction transport. Repository inventory contains no Java/Clojure client, C ABI or HTTP query service.

Fresh bounded example checks: extracted both exact Rust fenced blocks from the assigned page, wrapped them in fallible functions, and compiled them with `rustc --edition=2024` against this isolated copy's existing debug rlib. Both ran successfully and returned identical `Relation([])` bootstrap results. The only compiler warning was the example's intentionally unused rendered `text` variable. A data-only CLI query read its exact query text through `--file -`, with a temporary `$rows` EDN descriptor and `EDB_POSTGRES_URL` removed, and returned `#{["Ada"]}` on stdout. No Cargo suite or live durable test was rerun for unchanged behavior.

Reused inspected evidence: `tests-integrated-second.log` reports 43 library and 55 integration tests passed, including all six `edb_interfaces` tests, nine source-query tests, seven source-Pull tests, source submission roundtrip/identity tests, and ordinary/source/generated timestamp assessment tests. The durable tests were explicitly ignored in that log; it is not live durability proof. `native-workflow.log` separately records a successful live schema/transaction/query/Pull/log/index-pull/history/reopen workflow. `process-workflow.log` records successful independent writer/peer transactions and retries. `application-local-retry-after-fix.log` and `application-tls-first.log` record successful ordinary entity sources, automatic timestamps, receipts, speculation, current/history and application query/Pull behavior with both local and TLS transports. The earlier `application-local-first.log` contains a known failed mixed-source fixture and was not used as passing evidence. No remaining language-support parity gap was found; the assigned page is unchanged and no shared code edits, services, production resources, or commits were made.
