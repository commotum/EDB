# Data model implementation

Observed: the page already states the settled six-coordinate shared-record model, but `Datom`, canonical vocabulary facts, eager replay, cardinality checking and typed encoders have five-coordinate assumptions. Eager replay collapses an EAV regardless of contributor; schema projections count datoms instead of values.

Cause: contributor identity is absent from the stored coordinate, so assertion materiality and value multiplicity are conflated. Recovery and hashes encode that same conflation.

Bounded problem: preserve source in the common fact and index vocabulary, canonical genesis and schema information; require source in eager transaction entry points; retain EAVS contributions under global EAV withdrawal; encode and validate source without compatibility fallback. Transaction expansion, physical index trees and read/query integration are coordinated with their owners.

Approaches: a separate source relation would require joins and independently maintained attribution; a source-specific current record would violate shared cardinality. Select direct source on `Datom`, source-aware contribution membership, and ordinary value projections. Keep the existing EAV position index for global withdrawal, distinguish sourced additions locally. This keeps source identity independent of timestamp selection and preserves ordinary entity descriptions.

Acceptance: genesis contains ordinary `:db.source/system` and every genesis datom names it; six index orders compare complete coordinates; identical EAV from two sources remains live, repeated EAVS is redundant, third-source withdrawal removes both; cardinality/schema projections count distinct values; eager as-of/current/history retain attribution; new envelope versions reject old encodings and committed transactions reject mixed/invalid sources. Focused unit tests and integrated compilation reported separately.

Actual changes: `Datom.source` and six `IndexOrder` variants; canonical ordinary system-source entity 73; source-bearing schema-information builders and distinct-value schema projections; eager EAVS membership with global EAV removal; distinct `Database::values`, cardinality and schema cardinality-change validation; source-preserving current/as-of/history replay, source-sensitive invariant equality, same-source alteration-hook refresh; required `EntityRef` on `Database::with`/`with_defaults` with internal bootstrap explicitly naming system source; recovery source consistency, issuance, and allocation observations.
