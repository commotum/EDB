# Log API review

Observed: `database_value/log.rs` captures an immutable BlockSnapshot, validates T/Tx bounds without payload reads, resolves instant bounds through the captured AVET timestamp projection, and delegates both iteration and direct lookup to authenticated log readers. `query/sources.rs` returns six datom columns and typed reference transaction ids. `DatabaseValue::log_value` already supplies the same captured basis needed for source activity. Existing index tests establish reverse SAEVT order; transaction-model tests establish source-attributed empty transactions, but neither composes these with committed log reads and stable page boundaries.

Cause and bounded problem: the settled primitives exist, but the log page does not show how to capture a source timeline coherently, and the combined behavior has no durable acceptance test. Prove the composition, range/query shapes, and lazy construction without adding another activity API or storage structure.

Approaches: a dedicated source-log adapter would couple source selection, pagination, and payload reading and duplicate SAEVT. Scanning every log entry would preserve attribution but discard the source access path. Compose reverse SAEVT timestamp traversal with `db.log_value()` and `tx_data(Tx(entity))`; this keeps selection, capture, and payload authentication independently understandable. Pagination remains transaction-entity ordered, with instant bounds used only for log time selection.

Selected change: add a natural source-activity example to the assigned page and portable ignored durable coverage using explicit EDB_TEST_POSTGRES_URL. Reuse existing index visibility and log traversal machinery; change production code only if this experiment exposes a gap, after coordination.

Acceptance: tied instants include/exclude the whole group; empty transactions remain visible; reverse source timestamps and their log payloads retain attribution after cross-source retraction; a page resumed by transaction boundary on the same capture neither repeats nor admits later writes; T/Tx/instant/omitted/clipped/reversed bounds, invalid coordinates, six-column/truncated/bound-reference query output and source-kind/time errors agree with the page; integer cursor creation has zero payload stats and iterates incrementally. Existing excision tests cover generation retention and noHistory authoritative log contents; index tests cover durable order and cursor boundaries. No new large-transaction encoding test is needed here.

Experiment: durable timeline composition passed. The range/query test reached the documented `tx-data [[?e]]` example and failed with `query/function-binding`; six-column output and bound transaction output had already passed. Cause: generic `bind_output` correctly requires equal tuple widths, while log functions supply all six columns unconditionally. The bounded repair is to project TxData relation rows to the requested width (reject widths above six), retaining full six-column data for scalar/collection output. Changing generic binding would alter independent ground/fulltext/nested-query semantics and is unnecessary. Parent coordination requested for `src/query/sources.rs`.

Actual changes: `src/query/sources.rs` now admits tx-data relation bindings with one through six requested columns, projecting only that binding's rows. Wider bindings error before payload reading, including for an empty/genesis result. TxIds returns through its existing ground path; generic tuple/relation binding remains exact. Scalar and collection tx-data values retain E/A/V/Tx/S/Op. Corrected `LogValue::tx_data`'s native comment to state committed-range missing data errors. Added source activity capture/traversal/resumption example to the assigned page, with no new public API.

Results: `cargo test --test log_source_cutover -- --ignored --test-threads=1` passed 2/2 against the explicitly configured disposable PostgreSQL; `cargo test --test query_source_cutover` passed 9/9. New tests cover tied instant boundaries, instant-between selection, T/ref distinction, clipping/reversed bounds and invalid coordinates; zero-payload construction statistics and incremental/fused exhaustion; six-column and shortened tx-data relation binding, bound reference unification, full scalar/collection shape, wider binding errors, wrong-source/time errors and resource admission; empty/redundant transaction timestamps, source activity page resumption after later commit, original payload attribution and cross-source no-resurrection. Default new test invocation leaves both live tests ignored with the explicit setup reason. The new Rust documentation example compiled standalone against the built crate. Owned files passed rustfmt check.

Simplicity review: source selection remains SAEVT, visibility remains the shared current-record mechanism, and complete payload authentication remains the log reader. The change adds only a documented projection at tx-data's output boundary, preserving the independent exact-destructuring rule for other functions. No source timeline adapter, alternate log index, compatibility path, or per-operation source channel was introduced. Existing authenticated reader paths explicitly error on absent captured content and cursor errors fuse; corruption injection/storage encoding was not reimplemented in this page's tests. Storage generation/noHistory checks remain covered by the existing excision suite; backup/offline capture verification remains under the backup worker's ownership and is not a new log API implementation dependency.
