# Pull reference review

Observed situation: `prepare_attribute` consumes source-bearing EAVT/VAET cursor items and increments its selected vector for every contribution. A many-valued attribute therefore returns duplicates, and a positive limit can select fewer logical values than requested. The same routine feeds wildcard, explicit nested, component-default and recursive selectors. Index Pull intentionally offsets/projects every physical contribution under its explicit documented contract. Entity navigation already deduplicates adjacent forward values/reverse entities. Physical database cursors correctly preserve source attribution and must continue to do so.

Cause and bounded problem: projection counts are coupled to physical attribution. Pull and associative navigation must count distinct values (or incoming holders); index-pull must retain its documented per-datom traversal counts while each resulting Pull map contains distinct values. Visibility belongs to the existing captured database view, including global withdrawals before filtering; projection must not reconstruct it.

Approaches: globally collapse datoms would break source-bearing query/index/history access. A general set per selector is correct but adds allocations and sorting state despite ordered cursors. Adjacent dedup at projection consumes the existing EAVT/VAET logical groups in constant additional space and leaves visibility, attribution, nested expansion, transformations and budgets independent.

Selected implementation: compare each visible candidate's projected value with the last selected value before counting it in `prepare_attribute`. Keep existing source-aware cursor and cancellation callbacks. Retain index-pull per-datom results and offsets, including source contributions. Clarify Pull limits and shared value semantics naturally in the assigned reference.

Acceptance: scalar, many, reverse, component default, wildcard, explicit nested and recursive Pull shapes remain stable under a second source. Explicit/default/unlimited limits count logical values before expansion, including omitted empty nested maps. Entity forward/reverse navigation stays set-valued. Index-pull offset/limit and forward/reverse traversal preserve per-datom multiplicity while its maps project distinct values. As-of/since/source-filtered current reads honor global withdrawal; history remains attributed and Pull rejects it. Focused Pull regression tests and related query/view suites must pass.

Simplicity assessment: this keeps attribution and projection independent, composes with every selector through one existing preparation function, permits local reasoning from ordered cursor groups, and requires no adapter, compatibility path, extra index or source-aware selector syntax. Cursor budget charging still counts physical work, whereas limits count selected logical values.

Actual changes: `src/pull/attributes.rs` now skips adjacent equal forward values or reverse holder IDs before charging selected-value storage, applying limits, or scheduling nested work. Candidate reads continue to charge physical work and poll cancellation. The assigned Pull reference explains distinct values across sources and additional cursor work from repeated contributions. Entity navigation, execution, transform ordering and EDN parsing were reviewed and need no source-specific path. Root's `IndexComponents::Five` admission changes in `src/pull/index.rs` are retained; index-pull semantics remain the documented per-datom walk. No other documentation or outside-owned code was edited.

Validation: `cargo test --offline --test pull_source_cutover` passed all seven tests (latest run: 0.79 seconds). Coverage includes eager and speculative overlay reads; scalar, many, reverse (including reverse cardinality-one), component, wildcard, explicit nesting, recursive nesting and aliases/defaults; default 1000, explicit and unlimited logical limits; empty nested-map omission after selecting the prefix; transform-after-limit; entity traversal controls; lazy entity forward/reverse and component touch; captured as-of/since and source filters; cross-source global withdrawal and new-source reassertion; retained history attribution and rejection of history Pull/entity; index-pull forward/reverse per-datom result/offset behavior and five-component source boundaries with deduplicated maps; end-to-end indexed/forced-scan query Pull; and cancellation triggered while reading the second source contribution. The related database-filter suite (five tests) and query suite (nine tests) also passed. `git diff --check` for owned paths passed. Initial focused attempts caught a fixture API typo and a test expectation that incorrectly treated AVET seek as an equality constraint; both fixtures were corrected, with no production workaround. No services, PostgreSQL resources, production files, commits, or global formatting were used. No remaining owned behavior gap is known.
