# Index model cutover

Situation: the assigned page describes six source-bearing index orders and global EAV visibility. Eager roots and overlay roots currently store four orders; raw boundaries end at T; the durable descriptor frames eight trees. These representations cannot express the documented access paths.

Diagnosis: source has not reached keys, codec columns, routing boundaries, or current contribution membership. An EAV-only current key discards distinct sources. A source-first history range alone cannot decide global retractions.

Bounded problem: extend existing index mechanisms to six orders, retain all six datom fields, extend contiguous boundaries to five components, and retain multiple live EAVS contributions while EAV retractions clear them together. Keep AVET/SAVET eligibility and readiness shared. Database-value schema resolution and global source-first temporal visibility remain coordinated dependencies, not separate source worlds.

Approaches: separate source/time trees duplicate mechanisms and entangle attribution with activity; rejected. Extend existing typed orders and immutable tree/recent mechanisms. Source changes ordering and contribution identity, while visibility remains an EAV event concern. This follows Design in Practice's describe/diagnose/delimit/direction/design progression, and the talks' independent responsibilities and ability-to-change criterion.

Implementation: (1) prefixes/boundaries and eager/recent/overlay orders; (2) tree columns/routing/key comparison and incompatible codec versions; (3) twelve-tree descriptor and index preparation; (4) focused comparator, round-trip, prefix/boundary, contribution/retraction tests. Preserve existing API shapes and add only source-required components.

Acceptance: all six orders preserve E/A/V/T/S/bool; full and partial boundaries seek correctly; AVET/SAVET coverage agrees; same EAV from distinct sources survives, cross-source retract clears all; old codec versions reject; no ST tree. Report compiled/tested evidence and concrete pending integrations honestly.

Actual changes: all six eager, recent and speculative index orders retain source; AVET/SAVET use the same eligibility and schema-transition work. Five-component typed boundaries preserve the original four-component forms. Durable leaves add a source column, routing keys include source, tree format is version 6, and index descriptor kind 13 requires twelve trees. Legacy tree version 5 and descriptor kind 3 are rejected. No separate source/time tree was added. The assigned doc keeps its structure and explains shared global visibility and complete-group history omissions.

Shared mechanisms: current_eav_group resolves complete logical EAV history, retaining newest assertions per source since the latest strict-stored-value global barrier; same-T assertions survive. no_history_eav_group emits one barrier paired with every older assertion it withdraws, until the next barrier. Exact removals deduplicate the repeated barrier. EAVT preparation supplies identical witnesses to all history siblings; source-first local discovery does not make independent omission decisions. Selected-leaf gaps discard incomplete groups conservatively. IndexEavLookup::all loads all durable current contributions; EavsSet distinguishes speculative source contributions. Database-value temporal reads use the shared visibility helper. Storage maintenance maintains paired AVET/SAVET coverage and exact shared deletion witnesses.

Validation: cargo test --lib index_cutover --message-format short passed all 11 tests after the final counter/documentation changes (0 failed). Coverage includes all-six multi-leaf/multi-directory codec roundtrips and seeks, incompatible version rejection, five-component forward/reverse durable boundaries, source-prefix activity forward and newest-first reverse despite timestamp values in opposite order, eager AVET/SAVET eligibility, recent and overlay distinct contributions/global retractions, twelve-tree descriptor framing, shared noHistory barriers across every order, and safe complete versus partial EAVT discovery. git diff --check for owned paths passed. Tests used only the isolated checkout's in-memory tree/transaction fixtures; no service or production storage was contacted. No commits or global formatting were performed. Model, transaction, database-value and storage integration remain owned and validated by their assigned workers and the parent; there is no remaining owned compile/test blocker.
