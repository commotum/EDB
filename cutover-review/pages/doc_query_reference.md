# Query reference cutover

Observed situation: the reference already describes E/A/V/Tx/S/Op and existing query result forms. The initial implementation extends the AST, EDN compilation, persisted query encoding, relation matching, datom rows and source-first probes. Query pattern scoring still counts only E/A/V, and source-bound range probes discard ready AVET hints.

Cause and bounded problem: attribution is an ordinary fact coordinate, but the query planner's bound-coordinate inventory and range cursor were written around the former datom shape. Complete that extension without changing query names, find forms, function return shapes or relation-source literal semantics. Verify that global database visibility remains upstream of source matching.

Approaches and tradeoffs: scanning then matching source uses the existing semantics but loses the new source indexes. Source-first equality probes plus generic AVET ranges preserve correctness but omit source range locality. Extending the existing range cursor with an optional source reuses span bounds, exclusion splitting and controls while selecting SAVET when available; it requires one database cursor extension, to be coordinated with its owner. Choose that extension and count source in the existing bound-value scheduler.

Acceptance checks: source variables join to entity facts; numeric ids, idents and lookup refs match source with entity semantics; absent lookup refs return no rows. Six-position current/history and raw relation patterns preserve order. Cross-source withdrawal cannot resurrect an old assertion through source constraints, filtering, as-of/since composition or forced scans. Equal EAV from distinct sources collapses when source is omitted from the find/with basis and counts twice when source belongs to it. Diagnostics select SAEVT, SAVET equality and SAVET ranges when eligible, and source bounds influence clause scheduling. Query encoding roundtrips source-bearing patterns and keeps source-distinct prepared queries separate.

Evaluation: keep database visibility, coordinate resolution, index selection and projection as independent concerns. Source matching composes with the existing entity resolver and basis-set projection; no new source identity language, adapter or compatibility route is needed. Range locality must remain a physical choice with identical forced-scan results.

## Implementation and evidence

Completed the initial six-coordinate query work after reviewing every owned diff. `DataPattern.fact_source` participates in variable collection, diagnostic binding capture, raw datom matching, EDN compilation and portable query encoding. Source terms reuse `resolve_entity`/`unify_entity_term`, including lookup absence as a nonmatch. Datom and log tuple conversion preserves E/A/V/Tx/S/added ordering.

Added fact-source bound scoring in `execute.rs`. Extended the existing range state with an optional source; SAVET ranges share AVET's predicate constraints, exclusion spans, strict lower bounds, upper-bound stop, cancellation and work accounting. Coordinated the `database_value/cursor.rs` extension with the parent: AVET and SAVET now provide their own typed boundary to one query lower-bound helper. All source probes continue through database-value cursors, where complete EAV visibility precedes custom/source selection. No query-side visibility resolver or source-specific identity adapter was added.

The full parity review found an older raw-relation mismatch: removing blanks before calculating row width let explicitly wider patterns match short rows. Fixed the shared matcher to retain width before removing blank checks. EDN patterns with one or two supplied columns now use the existing `RelationPattern`, preserving their arity; database evaluation converts them through the existing datom-pattern mechanism. Three-to-six-column patterns retain `DataPattern`; no new model fields or compatibility path were needed. Both short database patterns and longer raw tuples retain their documented behavior.

Minimal reference edits explain visibility before source matching and ready SAVET ranges. Query grammar, names, argument order, find/result forms, fulltext output, function return forms and ordinary transaction metadata joins remain as documented.

Validation: `cargo test --test query_source_cutover` passed all 9 tests (latest run: 0.25s); owned-file `git diff --check` passed. Tests cover entity/source joins, numeric id and lookup-ref input/literal resolution, ident resolution on genesis, missing lookup nonmatches, duplicate EAV contribution basis/count/:with behavior, current/as-of/since/history and filter no-resurrection, SAEVT/SAVET equality selection and source-first scheduling, SAVET strict/excluded range parity with forced scans across views, six-position literal raw relations, short-row/trailing-blank arity, prepared source-sensitive cache keys, and portable query encoding roundtrip. Initial test attempts were blocked by a concurrently edited snapshot AVET/SAVET alternative-pattern type mismatch; the parent fixed it and all subsequent focused tests passed.

Evaluation of independent concerns: entity resolution defines coordinate meaning, database cursors define global visibility, the planner chooses physical locality, and find/:with basis formation defines observation identity. The implementation composes these existing responsibilities without adding a second source relation or branching the query result model. Raw relation width is structural data retained in the existing relation representation rather than an adapter to database semantics. Future index changes can replace the boundary/probe choice while the same resolution, visibility and projection remain valid. The focused tests demonstrate eager/speculative current and temporal parity; root owns complete-suite integration and durable storage/recovery acceptance. No remaining assigned query gap is known.
